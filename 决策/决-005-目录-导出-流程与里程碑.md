导出器：

- `--target story-long`：写 `设定/角色/{角色}.md`（主角卡或配角卡字段、三层标签、七维语言）、`设定/关系.md` 关系总览表；命盘不放进 `设定/`，只在 `设定/` 下放一个指向 `命盘/` 的说明。
- `--target story-short`：同上，按短篇模板裁剪。
- 其他 target：占位，按需再加；人物档案本身也可以直接交给套装用。
- 不传 target：只产人物档案。

实现（2026-09-24-12，scripts/export_story.py）：story-long 写 `设定/角色/{角色}.md`（主角卡或配角卡字段，后接三层标签、动机链、语言风格档案七维、人物弧线按阶段卡、关键节点与两难、亲密关系模式、别人眼里的他；literary 另有意象与视角）、`设定/关系.md`（关系总览表、关系演变、核心冲突关系）、`设定/来源/bazi-writing.md`（指回作者本目录的说明；放子目录是因为 story 的提交钩子把 设定/ 直属的散文件当角色卡查姓名字段）；story-short 只在 `设定.md` 里写标记段。字段映射与关系类型映射见 SKILL 3j；只用档案 text 一层不碰 sources，导出本过去术语检查（连"命盘"这个目录名也不进导出本）；卡末『作者补充』段重导出保留，起始章节、退场方式这些作者定的写待补充。关系类型只用 character-relations.md 的四型（冲突、联盟、亲密、权威），不用 artifact-protocols.md 那套亲情爱情敌对，因为 character-designer 引的是前者。

端到端实测（2026-09-25，靶子项目，一本扫榜选题的书，八个角色）跑通了扫榜、选题、排盘、档案、导出、character-designer 补设定、卷纲、三章正文，暴露的接缝与改法：（1）角色卡上写死的口头禅与标志动作被写手一章一次原样搬进正文，纯导出本贡献一处八字连串，其余照抄来自 character-designer 在『作者补充』段写的对白样本；改法是口头禅与标志动作按倾向写、导出栏后带注记、来源说明提醒对白样本要少并标明，SKILL 第 3 节。（2）三章正文里人物情绪全被翻成外部动作，没有过程；写手手上的 emotional-arc-design 是读者侧的弧线与爽点手册，没有人物侧的过程；改法是档案加可选段"情绪过程"（碰线、身体先动、盖法、余波，第 8.1 节表），导出成角色卡的"情绪过程（写戏用）"块，写章时 narrative-writer 读 `设定/角色/` 就在手边。（3）`命盘/` 与 `人物/` 放在 story 项目根与书名目录并列是对的（story 的追踪、一致性检查、提交钩子只读书名目录），只是没写明；SKILL 目录节与来源说明补了。（4）character-designer 的补充全写在『作者补充』段内，重导出不丢，接缝成立。（5）正文的重复句、不用成语、感官描写弱是 narrative-writer（sonnet）与 1700 行技法规则叠加的结果，归套装，不归本仓。（6）同日的对照实验（第二章的一场，三稿）：输入换掉解决有没有情绪过程，模型换成 opus 解决句子有没有生气，两层各管一样。（7）作者读定稿后两条反馈追到本仓：句尾否定占一成半，来路一半是八张卡里"不看人""不解释"式短句被写手照形，四段改肯定写法；"手按衣襟"是伏笔装置被写成标志动作、三章按了三回，伏笔物件改成只被觉出、碰它归卷纲的伏笔行管。随后作者问口头禅与标志动作有没有必要存在，结论是没有：卡上只要有一句可搬的话和一个可搬的动作，写手就每章搬一回，倾向写法、注记、限次都只是减量；正统小说认人靠说话的方式、选择与他人反应，重复句是主题装置一本书至多一个。段整个废掉，检查器报 error，身体习惯并进情绪过程的身体先动，story 模板那一栏填指路。

### 旧 5. 总体架构

```
计算核  scripts/bazi_core/     排盘、十神、藏干、格局、大运、流年、刑冲合害、神煞、调候、旺衰打分、用神、五运六气
搜索核  scripts/bazi_core/     同一包里：search.py 反推穷举打分与去重、arc.py 弧光匹配、matrix.py 多人矩阵
推演核  scripts/bazi_core/     timeline.py 年表、dilemma.py 两难、schedule.py 配角日程、ensemble.py 群像快照、stagecard.py 阶段卡草稿
规则层  references/            判定表与叙事映射表，每条带古籍出处；模型按表查
解读层  SKILL.md + 主会话      命盘档案 → 人物档案、矩阵注释、时间轴事件、两难选择
产物层  命盘/ 与 人物/         作者本与人物真相层
导出层  scripts/export_story.py  人物档案 → story 套装的设定文件（2026-09-24-12；export_public.py 是发布公开库的脚本，与此无关）
检查层  scripts/check-*.js     去术语检查、人物档案字段契约检查（导出本契约检查随导出器做）；check_divergence.py 换盘差异度
```

v0.1 设计把搜索核单列成 `scripts/bazi_search/`，实现时并进了 bazi_core 一个包，不再分（2026-09-24-11 对齐）。

设计模式沿用作者自己排盘项目的"命局档案"思想：旺衰喜忌只判一次，存成 JSON，之后所有解读以它为地基。格局按月令查表算定，不交给模型。

脚本语言：Python 标准库为主，Node 做结构检查器，输出 JSON 行。运行期零第三方依赖。

### 旧 14. 流程

1. 输入：题材、时代或架空、写法轮廓、人物数量、每人的约束或已有设定。
2. 脚本排盘或搜索，输出命盘档案 JSON。
3. 模型按规则表生成作者本推导与人物档案。
4. 脚本算多人矩阵，模型注释每条边。
5. 大运流年展开为年表，每个大事件改写为两难选择。
6. 配角日程与交汇点。
7. 群像推演：推出事件链，投影成大纲与细纲。
8. 跑去术语检查与契约检查。
9. 按需导出到目标套装。

几个人一起做时第 3 步拆成两趟，与第 7 步交错（样例书实测 2026-09-25，SKILL 流程节的五步）：先排盘与矩阵、日程、推演、线程（第 2、4、5、6、7 步的脚本部分）；再并行写各人档案的命局段；再写事件链与裁决，共用事实只认它一处；再并行写各人的年份段与阶段卡，引事件链的编号；最后进写作层。先写年份段再写事件链，每份档案会各自长出共用的事，事后要逐条裁。
