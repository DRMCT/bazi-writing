# 任务书：编配（流程第 3 步）

你是给这本书配戏的人之一。盘和底册告诉你这几个人各是什么样；你的活是定这本书为谁、为哪件事，他要什么、什么挡着，每对人之间横着什么，把它写成一页交作者裁。你不写事件，不排年份，不改档案。派工那一行给你：项目根、`$SKILL` 目录、作者对这本书说过的话（一段或几句，原样）、你这一版的方向、别的起草者已经占了的一事（各一句，你要躲开）、写到哪两个文件。

编配会同时起三个人，各配一版，互相看不见，作者挑一个、合两个，或都不要重来。三版要在要什么、谁是主线、开篇落在哪这三样上至少两样不同。构思那一步挑定的点子是起点，不是笼子：盘回来以后人和预想的不一样，照盘上的人重新配。

好故事的底子在这一页。人各是各的样子是盘给的；把他们放在一处能不能结出戏来，要靠你配。

## 先读（按序）

1. `$SKILL/references/戏剧层/问法.md` 第一组，十问。这一页写完，十问都要答得出；答不出的那一问写进交付的拿不准里。
2. 模板 `$SKILL/references/戏剧层/模板/编配.md` 与 `编配.json`（字段照它，尖括号的提示删掉）。
3. `命盘/群像/编配候选.json`：每对人的张力、牵绊、依据的 E- 编号，谁是主动的一头。它是候选不是结论：张力最高的一对不一定是主线，主线要合这本书的一问。
4. 各人的底册读者本 `人物/{名}.读者本.md`：性格表里、童年事件、谎言、需要与想要、抵抗线、亲密关系模式。只有命盘没有底册的人读 `命盘/{名}.json` 的 features。
5. `命盘/矩阵.json` 里主要几对的 draft；各人的 `命盘/{名}.弧光.json`（谷底与转折候选落在哪几年）。
6. `书/主题.md` 的命题（有就读；没有，这一页的前提句写完以后由主会话回填）。

## 怎么配

- 短篇先定一事，再定一人，一事要几个字说得出来。长篇定一人，再照构思挑定的盘子定每一段的一事：主角在这一段要什么、什么挡着，后一段从前一段的结果里长出来；每段的一事各用几个字说得出来。只知为一人、每段却没有一事，事就逐年铺开，成一串断了线的珠子。
- 长篇里线上的每个人都有他自己要的、自己的去处。对子表之外另列一张人表：他自己要什么、什么挡着、他这条线往哪去。
- 短篇的全书一问写读者翻页要知道的事：谁要什么、什么挡着、丢了会怎样。长篇每段一问，全书从头问到尾的是主题卡的命题，每段换一个样子再问一遍。要的是书里摸得着的东西，不写心境。
- 要的东西落在九个领域里的哪一个（感情、六亲、财富、事业与权力、身心、名誉与是非、学识与真相、迁徙与归属、创造与传承），题材不同落处不同。要不只是去拿一样东西：要保住手里的、要弄清一件事、要逃开一样追上来的，都算。
- 挡着主角的不一定是一个对手，有六类：人（也要它的、不给的、自己这边的）、规矩（律、门第、职分、行规）、东西（钱、路远、身子、手里没有的本事）、时候（期限、年纪、来不及）、不知道（真相被藏着，或他自己看错了）、自己（怕、信错的那句话）。挑这本书里最疼的那一类，可以不止一类；不要见了两个人就配成抢东西。
- 对子表写的是两个人之间横着什么，种类不止一种：同求一样东西；一个要、一个不给；一个要走、一个要留；一个知道、一个不知道；一个欠、一个不讨；各自要对方变成另一个样子。横着的东西要是书里摸得着的。各站哪边写成两句对着的话。候选里标同盟或淡的一对可以做副线，只要你写得出他们之间横着什么；写不出就不做。
- 谁主动可以改候选的判断，改了在那一格写明为什么。
- 拴住他们的要是走不掉的东西：同一间屋、一纸约、一笔钱、一个孩子、一桩谁也不能说的事。候选里标只撞不拴的一对，你另给一样；给不出，这一对不做主线。
- 一对人最好互为衬：一个的样子要靠另一个才看得见。
- 主角要的若是一个人，那个人不进背景：他不必是哪一条线的一头，只要不列进背景，推演照样让他当事件源。对子表依据一栏，除了这一对两人之间的边，也引他们各自对那个人的边。
- 短篇主线一条、副线至多两条。长篇三到五条线，每条线要碰得到主角的某一段，或者答得到命题；碰不到的砍。剩下的人是背景：可以在场，可以施压，不当事件源，不开线程。舍不得砍的线，问一句这件事能不能让已经在线上的人来做。
- 领域配权照这本书的一事定：这件事落在哪个领域，哪个领域就多挑；盘上年年都动、却与这件事无关的领域少挑。倍数在零点五到二之间。
- 起步是明还是暗：两个人之间的事从一开始就摆在面上，还是先在暗处。暗要两头对着暗，两个人心里都知道、面上都装不知道，才有戏；一头瞒到底、另一头蒙在鼓里，读者没处看。一头摆在面上、另一头当面应下转身按自己的来，写一头明一头暗，并写明哪一头。
- 开篇落在哪：挑一个读者头三百字就能知道谁要什么、什么挡着的时刻。不必是故事最早的一年。写到哪一年、什么场合、谁在场、谁要做哪一件事为止，这一件事怎么一步步走不写；开篇要用到的前情至多一句，也算进下面要列的事实里。开篇落在靠后的年份，等于替事件链定下了那一年的局面：把它定下的几样事实在开篇一节末尾逐条列出来，交作者点头，事件链照着走。开篇不落在最早一年的，叙述结构跟着它走：主题卡的叙述结构一节由主会话照编配回填，旧的与它不合以编配为准。再写开篇三章：第一章落在哪一刻、谁要什么谁挡着；前三章里读者手里先拿到什么（第一回兑现，第一章就给更好）；约一万字以内局面翻过来的那一回落在哪里。
- 这本书哪里不一样，老实写。写不出来，说明这一事还是别人书里的事，回去改一事。

## 不写

- 事件、年份的步骤、章。那是事件链的事。开篇那一件事是例外，照上面写到的那个细度。
- 台词。引号不进。
- 盘上的术语不进人话的几节（全书一问、前提句、主脑、开篇、哪里不一样）；对子表的依据一栏引 E- 编号。

## 交之前自查

- 你这一版的 json 与 md 主次、配权一致；跑一遍推演脚本看它读不读得进去，输出写到临时文件：

```
PYTHONIOENCODING=utf-8 PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.ensemble_run 命盘/甲.json 命盘/乙.json … --window 起 止 --main 主角 --casting <你这一版的编配 json> > <临时文件>
```

## 交付

写派工给的两个文件（三版各写各的，如 `人物/编配.甲.md` 与 `命盘/群像/编配.甲.json`；作者选定后主会话把那一版改名成 `人物/编配.md`、`命盘/群像/编配.json`）。自查那条推演命令的输出写到临时文件，不覆盖 `命盘/群像/推演.json`。回复只报：全书一问一句、主脑一人一事、主线副线各是哪一对、背景是谁、你拿不准的三处（一句一处）。作者裁的是全书一问、主脑与主线。文件写 LF、UTF-8 无 BOM。
