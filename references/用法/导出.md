# 导出到 story 套装

人物档案写完、检查过后，按需导出成 oh-story（story-long-write / story-short-write）的设定文件。`--out` 是 story 项目根（长篇）或短篇目录：

```bash
"$SKILL/.venv/Scripts/python" "$SKILL/scripts/export_story.py" 人物/林昭.json 人物/沈砚.json --target story-long --out ../书名 --main 林昭
```

```bash
"$SKILL/.venv/Scripts/python" "$SKILL/scripts/export_story.py" 人物/林昭.json 人物/沈砚.json --target story-short --out ../短篇标题
```

- story-long 写三样：`设定/角色/{角色}.md`（主角卡或配角卡的字段，后接三层标签、动机链、语言风格档案七维、情绪过程（写戏用；档案有这段才出，四拍加一行提示）、人物弧线按阶段卡、关键节点与两难、亲密关系模式、别人眼里的他）、`设定/关系.md`（关系总览表、关系演变、核心冲突关系）、`设定/来源/bazi-writing.md`（指回作者本目录的说明；放子目录是因为 story 的提交钩子把 `设定/` 直属的散文件当角色卡查姓名字段）。story-short 只在 `设定.md` 里写 `<!-- bazi-writing:start -->` 到 `<!-- bazi-writing:end -->` 一段（人设加关系表），文件已有就只换这一段。
- 字段映射：身份标签 ← 性格表里的身份层；外貌特征 ← 体质与外貌；性格关键词 ← 表现层底色、内核层、矛盾面；核心目标 ← 以为想要的；核心动机 ← 真正需要的；致命弱点 ← 抵抗线；口头禅 ← 同目录戏用页"他怎么被记住"那一问带引号的那一句（注明哪章哪场说由细纲排），没有戏用页或没给就填"无固定口头禅；腔调见语言风格档案，身体反应见情绪过程"（档案里没有口头禅与标志动作段，配角卡的标志性特征改填外貌）；角色定位或角色功能 ← 功能位，没有就取一句话人物真相；动机链的起因 ← 童年事件、约束 ← 谎言、风险 ← 秘密；配角的与主角关系 ← 两份档案"他人眼中的他"里提到对方的句子，没有就按矩阵边写。关系类型按矩阵边映射：官杀与财的边是权威型（谁在上写在括号里），印与食伤是联盟型，比肩联盟、劫财冲突；日支相冲刑害或两边互为忌仇再加冲突型，相合加亲密型。情感倾向按两边的用忌：都用喜为正面、都忌仇为负面、一用一忌为复杂。当前状态取"他人眼中的他"，没有就用回应倾向表那句人话；起始章节与退场方式是作者定的，写待补充，首次交汇的年份带在括号里；变化节点是故事窗口内的同步逆风与一顺一逆段，加线程。
- 性别与生年从档案 `chart` 指的命盘读；`--year` 故事起始年算年龄并标出当前阶段卡，默认取推演窗口起点；`--main` 默认取推演的 main，没有就第一份档案；矩阵、日程、推演按第一份档案的项目根自动找（`--matrix`、`--schedule`、`--run` 可指定），没有就少写对应内容，不报错。
- 只用档案里读者本那一层的文字，导出本天然过去术语检查（对 story 项目的 `设定/` 跑 check-terms，`--period` 给设定卡的时代）；字段在场、值可以待补充，沿用 story 的口径。每张卡与关系表末尾的 `## 作者补充` 段重导出时原样保留，退场方式、章节号、作者改动写那里；其余部分重导出会覆盖，改人先改 `人物/{角色}.json`。story 的 character-designer 在 Phase 2 补设定时也写在这一段（它会写登场与去向、分卷弧线、对白样本、写作红线），所以重导出不丢；但它写的对白样本会被 narrative-writer 原样搬进正文，样本要少、要标明是样本。样例 `examples/林昭/导出/story-long/` 与 `story-short/`：林昭主角加沈砚配角，裴恪只有命盘，只在关系表里。
