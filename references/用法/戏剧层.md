# 戏剧层：群像推演、编配、戏用页、事件链、梗概

盘给材料和时候，这一层把材料排成戏。任务书在 `references/任务书/`，起草者动笔前要答的问题在 `references/戏剧层/问法.md`。

## 群像推演

事件是共享的，两难是各人的。不让人物轮流出手，而是每个热年出一张事件卡，脚本把在场的人、各人赌注、各人回应倾向、旧账一次算全，模型对着卡写这一年的事件链，几轮由叙事定。

```bash
PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.ensemble_run 命盘/沈砚.json 命盘/林昭.json 命盘/裴恪.json --window 324 346 --main 林昭 --threads 命盘/群像/线程.json > 命盘/群像/推演.json
```

- hotYears 是热年：那一年有交汇点（边有当年才有的原因，且两端至少一人是候选年份，与日程同一条规则）；gaps 是连续的过场年，大纲里合成一句时间跳跃。
- 每张卡：source 事件源（交汇点里主机制烈度最高的人，同分主角先），event 直接是他那年的两难草稿；present 在场的人（与源同在交汇点的，加上当年对任一在场者有五行临身的）；stakes 各人当年的领域与权重，byPortraitOnly 为真的人只按画像反应、不生新事件，链条在他身上停；tendencies 每个非源在场者的回应倾向（回应倾向表：他看源的十神边乘用忌，lean 是靠近、躲或压、看，text 是表里的样子，modifiers 是按矩阵与快照事实挂上的修正）；threads 是重新上卡的旧账；openThread 是这张卡的两难若没解决该开的线程，抄进线程文件。
- 线程文件 `群像/线程.json` 作者维护：`{"schema": "bazi-threads/v1", "threads": [{"id": "TH-331-林昭-裴恪-感情", "people": ["林昭", "裴恪"], "domain": "感情", "since": 331, "status": "悬置", "note": "……"}]}`。悬置的线程在之后该对边再成交汇点、或任一方候选年份触及同一领域的年份重新上卡；任一方换运的年份列在线程的 rewriteYears，那一步人变了，账要改写；了结改 status。
- outline.volumes 卷按主角的大运切，带热年、配角换运的转折点、这卷开出的线程；segments 是热年成的情节段。细纲要场景节拍时加 `--months`，热年在场的人带十二流月。
- 事件链写在 `人物/推演.md`（作者本，不进正文）：按热年分节，先一段"牌面"，再逐步写谁先动、落到谁身上、对方怎么回应、悬置还是了结，每步末尾"｜溯源"引卡上的编号（Q-、E-、L-、J-、D-、TH-），核对：

```bash
PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.ensemble_run --check-chain 人物/推演.md --run 命盘/群像/推演.json
```

- 写法：回应倾向给的是方向不是结局，动多大看他押了多少；没押的人写"看着"就够；日柱相冲的当场发作，相合的事后才动；一顺一逆的两人对同一件事记的账不一样。事件链的结论要进某人的人物档案（秘密、年表与两难、阶段卡的关系变化）时引 TH- 与 Q- 编号，检查时加 `--run 命盘/群像/推演.json`。样例 `examples/林昭/`：三人 324–346 年八个热年，`人物/推演.md` 写了 331 与 337 两年。

## 编配、戏用页、事件候选、梗概与冷读

编配候选（每对人的张力与牵绊、谁是主动的一头；候选不是结论）：

```bash
PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.casting 命盘/甲.json 命盘/乙.json 命盘/丙.json --window 2003 2023 > 命盘/群像/编配候选.json
```

- 每对人给张力分与牵绊分，各带来由与矩阵的 E- 编号：同求（互看比肩劫财）、压与受（官杀）、用忌相反、日柱冲刑害是撞；六合、印与食神的边、互为用喜、一起在低处是拴。kind 为对子的两样都有；只撞不拴的一对要在编配表里另给一样拴住他们的东西。
- 编配表 `人物/编配.md` 由模型照任务书 `references/任务书/编配.md` 起草、作者裁；机器读的那几样抄进 `命盘/群像/编配.json`。`bazi-casting/v1`：main 主线一对、sub 副线（长篇至多六对）、background 背景的人、domainWeights 领域配权。`bazi-casting/v2` 另有几栏，都可空：timescale（短跨度、长跨度、回到关口年）；breakers 谁碎（`{"who", "by": 自己|别人当面|物证, "year"}`，只写名字也行）；families 家族（几组名字，可含上一代）；defaultFate 透给读者的默认下场（`{"who", "year", "reveal": 记得|梦|传闻|卦|旁人判断, "part", "outcome": 应验|改, "spill": 余波落在谁}`，年份要在默认下场年表里）；calendar 钟（`{"name", "month": 流月次序，寅月为一, "year": 只这一年，不写是年年, "who"}`）；objects 物件账（`{"name", "holder", "passes": [{"year", "to"}], "recognized": {"year", "by"}}`）。模板 `references/戏剧层/模板/编配.json`。

默认下场与前史（编配会之前就能跑，给写默认下场、前史两节的人当材料；推演里的 fate 一栏是同一份）：

```bash
PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.fate 命盘/甲.json 命盘/乙.json 命盘/丙.json --window 2003 2023 [--horizon 10] [--elders 命盘/甲父.json] > 命盘/群像/默认下场.json
```

- 默认下场 people[].entries：窗起到窗后 horizon 年（默认十年）的候选年份，编号 DF-名-年；一句人话候选（主机制与形态、押的是什么、这一年对这个人偏顺偏逆），events 是这个领域常落成的几样事，reveal 是透法的先后（按主领域排的写作建议）。shelfLife 是这个人的保质期：原本按窗起那一步大运写，换运那年起不准。
- 前史 people[].prehistory：窗前的候选年份，编号 PH-名-年；nails 为真是六到十二岁、钉下假话的候选。pastYears 是窗里冲年支（过去追上来）、伏吟（旧事重演）的年份；一条前史的 catchesUp 是这些年份里动的领域对得上它的。
- 上一代（`--elders`）只出前史，同一家族的晚辈冲年支的年份记进它的 catchesUp（家族在编配 families 里；没给家族对所有人看）。

推演读编配：

```bash
PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.ensemble_run 命盘/甲.json 命盘/乙.json 命盘/丙.json --window 2003 2023 --main 甲 --threads 命盘/群像/线程.json --casting 命盘/群像/编配.json > 命盘/群像/推演.json
```

- 背景的人不当事件源：只有他有事的年份，事落到在场的、押得最重的那个线上的人头上，背景的人记在卡的 driver。
- 领域配权乘到领域权重上，只改挑哪个领域当这一年的主领域，不动年表的事实；配权不大于一的领域连着做了两个热年的主领域，第三年让它退后。
- 每张卡多一组 candidates：在场各人自己的事（kind 个人），加当年每个交汇点边上的事（kind 边，带两头各自的回应倾向 sides、线 line 是主线副线还是旁线）。已按烈度加主次排过，事件链起草者从里面挑。
- 回应倾向多一栏 textOpen：同一个倾向摆到明处的样子。线程在卡上带 pressure（第几回上卡）与 escalate（到第三回为真），到了第三回挂修正项取明处那一档。
- 线程文件可用 `bazi-threads/v2`：状态四个，埋、压、响、余波（旧的悬置读作压、了结读作余波）；另有 plan（`{"year": 哪一年响}` 或 `{"mute": "留哑的理由"}`）、open（明或暗）、knows（谁知道、哪一年知道的）。
- outline 每卷多 climaxCandidates：高潮年的前三个候选与来由。

人物与事件线：推演另有几栏，旧栏不动：

```bash
PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.ensemble_run 命盘/甲.json 命盘/乙.json 命盘/丙.json --window 2003 2023 --main 甲 --threads 命盘/群像/线程.json --casting 命盘/群像/编配.json [--elders 命盘/甲父.json] [--guests 命盘/客一.json 命盘/客二.json] [--horizon 10] > 命盘/群像/推演.json
```

- timescale：编配给的，或按窗长推定（不过两年是短跨度，否则长跨度）。短跨度卡上自动带 months，另出 monthGrid：窗里每个月谁的流月被引动、挂了哪口钟。回到关口年另出 returns：各人窗前最烈的三个热年（六岁起），单元回到谁的哪一年由事件链挑。
- fate：默认下场与前史，同 fate 脚本；编配透了几条（defaultFate）就多一个 book：透给读者的原本覆盖到哪一年（coversTo），之后交给谁（handover）。
- 每张卡多一栏 sources，过场年的放在 offCard（只有年年都有的钟的年份不单列）：默认下场到点（透过的带 revealed）、过去追上来（冲年支、伏吟的年份，带对得上领域的前史）、对手出招（上一张卡里躲或压、押得重的那一头，他下一个候选年份）、家人出招（同一家族里他是对方的官杀，他的候选年份）、得知与认出（线程上卡时不在 knows 里的那一头；物件账写了哪年被认出，或原主与持有人同在一张卡，认出以后不再提）、局与日历（钟挂上那个月，带同月流月被引动的人）。sourceKinds 是十种源的对照表，主角布局与关系自己往前走不由盘给。
- 给了编配，卡上还有 breakers（谁碎名单里在场、这一年是他候选年份或编配定在这一年的人）；源是主角的那一年另有 dilemmaTo：两难可以给的在场的人，谁碎的排前。
- 单元客（`--guests`）不进交汇点，出 guests：entry 是他书前最近的热年（找上门的那件事），course 是他在窗里的默认下场，nails 是钉下假话的那一年，breaker 是编配谁碎里他那一行；这是速生三问的底。
- 上一代与单元客的名字不能与推演的命盘重名。编配里出现的上一代、单元客要给盘，不然报错。
- 事件链（`--check-chain --drama`）每个热年多两栏。源：十种之一起头，几种用顿号分开，分号后写为什么（旁人求上门、班底派活、单元客入口都认作那一种）；卡上 sources 没有的那一种报 warn，连着三个热年只有热年出事报 warn。默认下场：`DF-名-年 透／应验／改`，可空，写无也行，过场行里也认；编配透的那几条没写哪一年透、窗里到点了没写应验还是改是问题；应验不在到点那一年、改在到点以后、没透先兑现、与编配的 outcome 不一样、编配没写透的，报 warn。warn 一行带 `"level": "warn"`，不影响退出码；汇总行多 warnings、sources（各种源几回）、defaultFate（透、应验、改各几条）。

戏用页（一人一页十问，任务书 `references/任务书/写档案_戏用页.md`，模板 `references/戏剧层/模板/戏用页.json`）：

```bash
node "$SKILL/scripts/check-drama.js" 人物/甲.戏用页.json --matrix 命盘/矩阵.json --timeline 命盘/甲.年表.json --run 命盘/群像/推演.json
"$SKILL/.venv/Scripts/python" "$SKILL/scripts/drama_render.py" 人物/甲.戏用页.json            # 排戏的人与检查读的一页
"$SKILL/.venv/Scripts/python" "$SKILL/scripts/drama_render.py" 人物/甲.戏用页.json --author   # 带来历与编号
```

- 十问：他要什么、谁挡着、他怎么去要、他信的那句话（假话或信条）、他真正缺的、碰哪里会疼、他瞒着什么、他怎么说话、别人拿他当什么、他从哪儿走到哪儿。第六问每根线五拍：碰线、身体先动、盖法、破、余波；假话页至少一条破，信条页不要求。五拍是上限。
- 页级 belief：假话（默认）或信条。信条页第四问写他拿来过日子的那句话、谁来挑战、怎么走，渲染成他信的那句话；整页没有破只报 info。主角默认信条，碎给编配谁碎一节挑的人。
- 破那一行可带 by（谁来破）：自己、别人当面、物证；不带算自己，渲染时标在破后面。
- 十问之后七个附问，可空，有就按次序排在后面：他被叫什么、他知道哪一层、他信错了谁、他对谁演什么、他跟谁怎么交手、他独一份的是什么、他怎么被记住。只有最后一问许一行带引号（口头禅）。十问超过一千八百字、附问超过六百字报 warn；交手一问一对一行，不算进附问字数，单行超过九十字报 warn。
- 每行标来历：盘（带编号）或定（编配或作者定的，写 ref）。铁律第 4 条对底册照旧；戏用页上作者与编配定的事可以没有盘上的编号，这是铁律第 1 条。
- 第七问事件链写完以后补，补完带 `--final` 再查。
- 破按这个人自己的常态量：他做了第三问里不肯做的那件事，就是破。三级：漏、说破、碎。表 `references/手段与破法.md`。
- 写完，主线副线上每一对做一回对手戏测试：任务书 `references/任务书/对手戏测试.md`，低一级的模型，只读两人的两页，答这两人关在一间屋里会为什么撞起来、谁先开口、谁先退。答不出或客客气气散了，回去改这两页。

事件链按新写法查（每卷有骨；每个热年有源、因、事件、选择、知情、线程、默认下场、主线温度、读者；每步写以为与实际、标明或暗；第三回上卡的线要升级；埋着的线要写哪一年响）：

```bash
PYTHONPATH="$SKILL/scripts" "$SKILL/.venv/Scripts/python" -m bazi_core.ensemble_run --check-chain 人物/推演.md --run 命盘/群像/推演.json --threads 命盘/群像/线程.json --drama
```

检查器不查、交给事件链任务书的两条：编配的每一段主角落一回下风（真吃亏或被逼到只差一步，出手的人与手段各段不同）；几个人的破挨在一段里的，谁来破要分开。

梗概与冷读：事件链写完照 `references/任务书/梗概.md` 出 `人物/梗概.md`（全书一页、每卷一页、开篇的场面提要，人话），交冷读代理（`references/写作层/任务书/冷读.md`，没有任何上下文，低一级的模型，两个）。冷读答不出这本书讲谁、他要什么，或者说哪一卷都想放下，回编配或事件链，不往下写。作者读梗概，作者的判决压过冷读。
